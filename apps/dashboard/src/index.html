Workflows — View all submitted workflows. Each workflow is a multi-stage execution: a Plan is created, the plan is Executed, the result is Reviewed, optionally Revised, and then Synthesized into a final report. Review prefers an independent runtime, but single-runtime deployments fall back to the same runtime so the workflow can still finish.

Runtimes — Connected agent runtime nodes that process workflow stages. Each runtime registers its own capabilities (skills it can perform). The scheduler matches workflow stages to the most capable runtime based on capability levels, availability, and cost. Runtimes communicate via the A2A protocol (Agent-to-Agent).
